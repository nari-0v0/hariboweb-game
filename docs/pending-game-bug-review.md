# PR 대기 — 원정대 오래된 강화 화면에서 다음 단계까지 결제

- 저장소: nari-0v0/hariboweb-game, 기준 커밋 878637d394eee071bb9de85d71e4d1e50ea9a35b.
- 근거: src/views/journey.tsx 665–691, 705–717. 훈련과 장비 폼이 현재 단계와 가격을 보여 주지만 항목 키만 전송한다. src/journey-db.ts 56–84에서 서버는 요청이 들어올 때 현재 단계를 다시 읽고 그 가격으로 결제한다.
- 발생 예시: 두 탭에서 같은 훈련 Lv.0 화면을 열고 첫 탭에서 결제한다. 두 번째 탭에서 그대로 누르면 Lv.0 → Lv.1로 표시된 요청이 실제로 Lv.1 → Lv.2를 결제한다. 첫 결제 이후 두 번째 요청의 조회가 시작되는 연속 제출에서도 가능하다. 재화와 강화 가능 단계가 충분해야 한다.
- 영향: 화면에 표시되지 않은 단계의 젤코인 및 장비 재료가 차감될 수 있다.
- 수정 방향: 폼에 표시된 현재 단계를 제출하고 DB 갱신 조건에 사용한다. 첫 제출이 성공한 폼을 다시 제출하면 가격과 단계를 갱신한 화면으로 안내한다.
- 검증 상태: 폼과 저장 코드 흐름 확인. 브라우저에서 두 탭으로 재현하는 테스트는 아직 실행하지 않음.

# PR 대기 — 사건파일 오래된 탭이 다른 진행 중 사건을 덮음

- 저장소: nari-0v0/hariboweb-game, 기준 커밋 878637d394eee071bb9de85d71e4d1e50ea9a35b.
- 근거: src/views/escape.tsx 720–745. 사건 목록의 전환 폼은 전환 여부만 보내며 화면에 있던 판 ID는 보내지 않는다. src/index.tsx 1006–1020에서 요청 시점에 진행 중인 판을 다시 찾고, 선택한 사건과 다르면 그 판을 종료한다. src/escape-db.ts 54–58은 종료된 판을 quit 상태로 바꾼다.
- 발생 예시: 사건 A를 진행 중인 상태로 두 탭에서 목록을 연다. 첫 탭에서 사건 B로 바꾸고 진행한다. 두 번째 탭의 A 목록에서 사건 C를 열면 서버는 A 대신 현재 진행 중인 B를 덮는다. B를 다시 열면 처음부터 진행한다.
- 영향: 오래된 화면이 사용자가 그 화면에서 보고 있지 않은 새 사건의 진행 상황을 잃게 할 수 있다.
- 수정 방향: 목록에서 본 판 ID를 전송하고 그 ID가 아직 현재 판일 때만 전환한다. 조건 검사와 종료 및 새 판 생성은 함께 처리한다.
- 검증 상태: main 폼 및 라우트의 코드 흐름 확인. 두 탭 재현 테스트 미실행.

## 같은 전환 경로의 별도 실패 조건

기존 판을 닫는 UPDATE(src/escape-db.ts 56–59)와 새 판을 만드는 INSERT(38–53)는 별도 DB 호출이다. 현재 탭에서 A를 B로 정상 전환하더라도 A 종료가 커밋된 직후 B 생성 요청이 DB 오류로 실패하면 A는 quit 상태로 남고 B는 없다. 오류 화면에서 재시도해도 A의 진행은 복구되지 않는다. 오래된 탭 대응과 함께 같은 트랜잭션으로 처리하고 새 판 생성 실패 시 기존 판이 유지되는지 확인한다. 코드 흐름 확인, DB 실패 주입은 미실행.
